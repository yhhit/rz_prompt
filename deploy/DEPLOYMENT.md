# 提示词资产维护与业务库导入指南

本文档说明提示词资产库的分层维护规范、普通软件套图模板与工控界面套图模板的差异化治理要求，以及本地校验后导入目标业务数据库提示词配置表的标准流程。

---

## 1. 资产分层与数据流向

1. **分品类源头维护（`UI参数/*.md`）**
   - 所有新增或修订的单套 UI 视觉参数，优先在 `UI参数/` 下对应的行业分类文件中修改（如 `办公软件-50套.md`、`工业控制系统-100套.md` 等）。
   - 每套参数须包含完整的结构化维度：`Visual Differentiation`、`Target Viewport / UI Scale`、`First-glance Signature`、`Background & Surface Language`、`Component Scale`、`Software Type`、`Subtype`、`Window Frame / Title Bar`、`Skeleton Type`、`Navigation Pattern`、`Colors`、`Typography` 等。
2. **全量参数聚合（`总体`）**
   - 将各活跃分类下的 UI 参数按统一格式合并，套与套之间严格使用独立行 `---参数分隔符---` 分隔。
   - 已停用的历史风格存放于 `归档/` 目录，不进入活跃聚合文件。
3. **业务提示词母版组装（`完整提示词`）**
   - 在聚合参数集外层封装角色指令、选参过滤规则、页面提示词占位槽位（登录页 + 第 1 个功能页 + 后续保持视觉一致性的功能页）以及严格的分段输出协议。

---

## 2. 普通套图模板与工控套图模板维护规范

在实际生产场景中，业务系统的提示词配置表通常将**普通软件界面套图模板**与**工业控制界面套图模板**拆分为独立记录维护：

### 2.1 普通软件界面套图模板
- **适用范围**：办公软件、数据分析系统、建模软件、工具软件、设计软件、监控软件、桌面客户端及移动端 APP 等非工控面板类系统。
- **核心规范**：
  - 必须携带原生桌面窗口标题栏（Windows 顶部窗口控制栏或 macOS 左上角三色窗口按钮）或对应移动设备视口特征；
  - 严格排除深蓝色背景主题风格，避免落入通用后台表格管理界面；
  - 第 1 个功能页（`PROMPT START 2`）确立整套软件的基准视觉骨架，后续功能页（`PROMPT START 3` 起）均须保持同一套界面框架与控件语言的一致性。

### 2.2 工业控制界面套图模板
- **适用范围**：PLC 控制、SCADA 监视、HMI 触摸屏、嵌入式工控终端、产线联机调试等工业软件。
- **核心规范**：
  - `Industrial Terminal Type`（工业终端类型）优先级高于圆角、阴影与配色；
  - 明确区分 **HMI 触摸屏面板端**（大按钮、大字号、状态指示灯、硬边框、单屏分页）与 **工程/调试上位机**（高密度点表、对象树、属性栏、底部实时日志），严禁在同一套系中混用端型特征；
  - 同样遵循移除同质化深蓝色科技大屏背景的色系约束。

## 3. 本地格式校验清单

每次修改提示词模板并准备导入业务库前，须在本地完成以下四项静态校验：

1. **占位变量完整性检查**
   确认母版中保留目标业务系统所需的动态模板变量，拼写与大小写无误且未被意外转义：
   - `{$system_name}`（软件系统名称）
   - `{$system_type}`（系统类型）
   - `{$menuCount}`（总页面数量）
   - `{$menu_structure}`（菜单功能结构）
   - `{$extra_remark}`（外部传入的补充说明，无内容时保持留空，禁止提示词自行编造）
   - `{$选择第几套UI参数}`（确定性取模选参索引）
2. **分隔符与输出标记检查**
   - UI 参数块之间统一使用 `---参数分隔符---`；
   - 输出协议块必须完整包含 `---适合的UI参数编号---`、`---最终选中的UI参数编号---`、`---PROMPT START 1---`、`---PROMPT START 2---`、`---PROMPT START 3---` 及配对的 `---PROMPT END---`，以便下游解析器按标记无损切分。
3. **色系与禁用词扫描**
   - 核查新增 UI 参数的 `Colors` 字段与 `Background & Surface Language` 未引入被禁用的深蓝色主背景，且不包含已归档的通用管理后台（SaaS Admin / CRM 后台）风格描述。
4. **敏感信息脱敏检查（公开仓库强制要求）**
   - 提交前执行 `git diff` 复核，确保所有文件不含任何服务器地址、域名、内部路径、账号标识或密钥信息。

---

## 4. 导入目标业务库提示词配置表流程

1. 在本地完成上述校验并通过小样本渲染对比测试（可参考 `test` 文件结构进行回归对比）。
2. 将更新后的**普通套图完整提示词**与**工控套图完整提示词**分别同步至目标业务数据库的提示词配置表对应记录中（更新前先备份原表记录内容以便快速回滚）。
3. 触发单笔测试任务，验证下游解析器能正常提取 `---最终选中的UI参数编号---` 及全部 `---PROMPT START N---` 页面提示词，且首图与后续功能页视觉风格一致。
4. 验证通过后，在本仓库提交 Git 变更并推送至远端 `main` 分支归档留痕。
