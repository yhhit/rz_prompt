# 办公软件 UI参数（50套）

## 生成目标

生成 50 套办公软件 UI 参数。该类别必须优先理解为长时间使用的办公、协作、文档、日程、列表、轻表格类软件，而不是后台管理系统、工控/监控终端、设计工具或移动娱乐 App。

常见范畴包括：

- 文档协作软件
- 日程 / 任务桌面工具
- 轻量表格 / 轻表格软件
- 邮件 / 三栏阅读工具
- 知识管理 / 笔记软件
- 会议 / 项目协作软件
- 办公设置 / 个人工作台

核心要求：

1. 必须舒适、清晰、适合长时间使用。
2. 应内容优先，而不是业务后台优先。
3. 不包含具体业务逻辑，但要有明确的桌面应用骨架。
4. 差异化主要来自：界面子类型、内容组织方式、协作区/列表区/编辑区比例。

## 一、总风格规则

- 长时间使用不疲劳。
- 多使用暖白、浅灰、柔和绿色、青绿色、棕色等自然色。
- 可采用卡片、分区、柔和圆角，但不能过度像移动 App。
- 避免强科技大屏感、过暗视觉、工控/监控感。
- 避免复杂后台管理系统骨架。
- 避免设计/建模画布工具骨架。
- 避免高密度配置表中心骨架。
- 必须带有操作系统窗口标题栏或桌面应用窗口框架，不能像无标题栏的移动 App 页面或纯网页落地页。

## 二、办公软件真正的差异来源

办公软件不应主要靠以下方式拉差异：

- 强科技暗黑风
- 后台管理式导航和表格
- 工控/监控面板
- 大量炫酷动效
- 移动 App 大卡片感过强

真正可用的差异化维度：

1. 子类型
2. 内容区 / 列表区 / 协作区 / 编辑区比例
3. 阅读密度
4. 辅助侧栏组织方式
5. 富文本、日历、列表、表格、目录树的骨架差异
6. Windows / macOS 桌面应用气质
7. 长时间阅读舒适度

## 技术栈 / 渲染范式优先规则

- Rendering Paradigm: `Native desktop application / desktop web application`
- UI Framework: `WPF / WinForms / AppKit / SwiftUI / Office Ribbon / Electron-like shell`
- Component Language: `native title bar, ribbon or command bar, tree view, tab control, rich text area, property pane, status bar, secondary sidebar`
- Native Control Level: `desktop端 high/very high；Web协作端 medium`
- CSS Styling Level: `桌面端 none/low；Web协作端 medium`
- 本节只描述界面渲染方式、框架和控件语言，不描述业务场景。

## OS / Era 使用规则

- 推荐 OS Family: `Windows / macOS / Web`
- 推荐 OS Era: `Windows 11 办公套件`、`macOS Ventura/Sonoma 办公软件`、`现代Web协作工具`
- 少量可用: `Windows 10 桌面工具`
- 避免: `Windows XP/Win7 老办公`、`Industrial HMI`、`监控终端`、`移动App首页骨架`
- OS Visual Traits: `舒适长时间阅读、内容/列表/辅助侧栏、柔和卡片、清晰内容区、低疲劳配色`
- Window Frame / Title Bar: `必须体现操作系统窗口框架；Windows 方案应有顶部标题栏、窗口控制按钮、应用标题/搜索/工具区；macOS 方案应有左上红黄绿窗口按钮、融合式工具栏或半透明侧栏；Web 协作工具也应表现为桌面浏览器/桌面应用窗口，而不是无窗口的移动App页面`

## 四、办公软件结构骨架禁忌

### 常见错误骨架

以下结构会让办公软件跑偏：

- 后台管理系统左侧菜单 + 表格中心骨架
- CRM / OA 重业务流程后台骨架
- 工控屏 / 监控大屏骨架
- 设计/建模画布中心骨架
- 移动 App 首页骨架
- 游戏/娱乐界面
- 强科技暗黑大屏界面

### 适合的正确骨架

- `富文本分栏编辑型`: 左侧树形导航 + 中央列表/编辑区 + 右侧辅助面板
- `日程任务`: 左日历/清单 + 中央列表 + 右详情
- `轻量表格`: 工具栏 + 轻量表格 + 右注释/详情
- `邮件沟通`: 左邮箱/频道 + 中列表 + 右阅读/详情
- `知识笔记`: 左目录 + 中内容区 + 右标签/引用
- `会议项目`: 分组列表 + 卡片区 + 活动区
- `个人工作台`: 概览卡 + 列表区 + 设置/偏好区

## 少量套数强差异化规则

当某个大类下只有 6–10 套真实参数时，不能只做同一骨架的配色变化；每套都必须像不同软件。生成时优先遵守以下硬约束：

- 每套必须有不同的 `Target Viewport / UI Scale`：例如手机 390×844、平板 1366×1024、桌面 1440×900、工作站 1920×1080、HMI 1024×768、双屏/超宽 2560×1440。
- 每套必须有明确的 `First-glance Signature`：用户第一眼能看到的差异，例如大标题手机卡片、硬边框工控按钮、深色终端、Ribbon 工具栏、三维视口、图表矩阵、浮动小窗。
- 每套必须拉开 `Component Scale`：有的整体控件很小很密，有的按钮和列表很大，有的中等办公密度，有的触控大字号。
- 每套必须拉开背景与容器语言：纯白/浅灰/米色/深蓝/黑灰/玻璃/硬边框/网格底/终端底，不允许连续多套都是白底卡片。
- 每套至少在 `目标分辨率、整体缩放、背景颜色、容器形态、导航骨架、控件密度、字体尺度、边框/阴影` 中变化 5 项以上。
- 如果两套同属浅色风，必须一个偏冷灰硬边框，一个偏暖色大留白，或者一个高密度表格，一个大控件卡片，不能只换主色。
