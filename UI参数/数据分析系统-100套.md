# 数据分析系统 UI参数（100套）

## 生成目标

生成 100 套数据分析系统 UI 参数。该类别必须优先理解为以下软件范畴，而不是普通后台、监控大屏、工控屏或设计画布：

- BI 分析平台
- 指标看板
- 数据探索型
- 报表透视系统
- 桌面专业分析工具
- 运营分析仪表盘
- 深色专业分析面板

核心要求：

1. 必须服务于图表阅读、指标比较、筛选探索和数据明细查看。
2. 允许有 Dashboard，但不能变成炫酷驾驶舱或赛博大屏。
3. 不包含具体数据指标或业务逻辑，但要有明确的数据分析骨架。
4. 差异化主要来自：分析子类型、图表/筛选/表格组织方式、平台气质和信息密度。

---

## 一、总风格规则

- 信息层级清晰，适合长期阅读图表。
- 可使用浅色分析风、深色分析风、冷灰分析风、克制深海分析风。
- 避免发光网格、霓虹堆叠、科幻大屏、游戏 HUD。
- 不使用 PLC/HMI 控制屏骨架。
- 不使用普通配置后台骨架。
- 不使用设计软件画布中心骨架。
- 不使用移动 App 信息流骨架。

## 二、数据分析系统真正的差异来源

数据分析系统不应主要靠以下方式拉差异：

- 炫酷霓虹
- 科幻背景
- 大屏视觉堆叠
- 纯卡片换色
- 过多装饰图标

真正可用的差异化维度：

1. 子类型
2. 图表区、指标区、筛选区、明细表的占比
3. Web 分析平台 or 桌面分析工作台
4. 图表密度
5. 筛选探索方式
6. 深浅体系
7. 多面板分析结构

## 四、结构骨架禁忌

### 常见错误骨架

以下结构会让数据分析系统跑偏：

- PLC/HMI 单屏控制骨架
- 工控值守终端骨架
- 纯普通后台配置表单骨架
- 设计/建模软件画布中心骨架
- 移动 App 信息流骨架
- 赛博朋克大屏驾驶舱
- 只有卡片没有图表/筛选/明细的数据假看板

### 正确骨架

- `BI指标看板`: 顶部筛选 + 指标卡 + 图表网格 + 明细表
- `数据探索型`: 左数据源树 + 中图表区 + 右属性 + 底部数据网格
- `报表透视`: 筛选区 + 透视表 + 图表摘要 + 导出工具栏
- `运营分析仪表盘`: 时间筛选 + 指标卡 + 趋势图 + 列表
- `深色专业分析`: 深色指标面板 + 趋势图 + 对比区 + 明细表
- `桌面专业分析工具`: 数据树 + 多图表工作区 + 参数面板 + 数据网格

## 少量套数强差异化规则

当某个大类下只有 6–10 套真实参数时，不能只做同一骨架的配色变化；每套都必须像不同软件。生成时优先遵守以下硬约束：

- 每套必须有不同的 `Target Viewport / UI Scale`：例如手机 390×844、平板 1366×1024、桌面 1440×900、工作站 1920×1080、HMI 1024×768、双屏/超宽 2560×1440。
- 每套必须有明确的 `First-glance Signature`：用户第一眼能看到的差异，例如大标题手机卡片、硬边框工控按钮、深色终端、Ribbon 工具栏、三维视口、图表矩阵、浮动小窗。
- 每套必须拉开 `Component Scale`：有的整体控件很小很密，有的按钮和列表很大，有的中等办公密度，有的触控大字号。
- 每套必须拉开背景与容器语言：纯白/浅灰/米色/深蓝/黑灰/玻璃/硬边框/网格底/终端底，不允许连续多套都是白底卡片。
- 每套至少在 `目标分辨率、整体缩放、背景颜色、容器形态、导航骨架、控件密度、字体尺度、边框/阴影` 中变化 5 项以上。
- 如果两套同属浅色风，必须一个偏冷灰硬边框，一个偏暖色大留白，或者一个高密度表格，一个大控件卡片，不能只换主色。
