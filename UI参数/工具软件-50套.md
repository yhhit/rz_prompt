# 工具软件 UI参数（50套）

## 生成目标

生成 50 套工具软件 UI 参数。该类别必须优先理解为轻量、任务导向、效率优先的软件，而不是复杂后台、监控大屏、移动内容 App 或专业创作软件。

常见范畴包括：

- 轻量桌面配置工具
- 单任务 Web 小工具
- 批处理工具
- 文件 / 数据转换工具
- 参数设置工具
- 日志 / 队列处理工具
- 工程辅助工具
- 小型检查 / 修复工具

核心要求：

1. 必须任务明确、结构轻量。
2. 不应复杂业务化，不应平台化。
3. 不包含具体业务逻辑，但要有明确的工具软件结构。
4. 差异化主要来自：任务类型、输入/输出组织方式、配置密度、桌面或轻 Web 气质。

## 一、总风格规则

- 简洁、轻量、效率优先。
- 可以紧凑，但不能拥挤。
- 装饰元素少，避免大屏、游戏、营销和过度视觉包装。
- 可以偏桌面端，也可以偏轻 Web 工具。
- 不使用复杂后台多层导航骨架。
- 不使用设计软件画布中心骨架。
- 不使用移动内容流骨架。

## 二、工具软件真正的差异来源

工具软件不应主要靠以下方式拉差异：

- 奇怪配色
- 大量卡片装饰
- 复杂平台导航
- 业务后台流程
- 创作软件式大画布

真正可用的差异化维度：

1. 子类型
2. 输入 / 输出骨架
3. 任务步骤结构
4. 配置密度
5. 日志 / 队列 / 结果区占比
6. 桌面工具 or 轻 Web 工具
7. 操作按钮组织方式

## 四、工具软件结构骨架禁忌

### 常见错误骨架

以下结构会让工具软件跑偏：

- 复杂后台管理系统骨架
- CRM / OA 业务流程系统骨架
- 监控大屏 / 值守终端骨架
- 专业设计/建模画布中心骨架
- 移动 App 信息流骨架
- 游戏工具界面
- 营销官网式大视觉骨架

### 适合的正确骨架

- `轻量配置工具`: 左配置分组 + 右参数表单 + 底部状态条
- `单页 Web 工具`: 中央输入区 + 结果区 + 操作按钮行
- `批处理工具`: 队列列表 + 参数区 + 进度/日志区
- `文件/数据转换`: 文件列表 + 转换设置 + 输出结果
- `日志/队列处理`: 队列列表 + 日志面板 + 过滤工具条
- `检查/修复工具`: 检查项列表 + 结果摘要 + 修复动作
- `工程辅助工具`: 参数网格 + 任务区 + 底部控制台

## 少量套数强差异化规则

当某个大类下只有 6–10 套真实参数时，不能只做同一骨架的配色变化；每套都必须像不同软件。生成时优先遵守以下硬约束：

- 每套必须有不同的 `Target Viewport / UI Scale`：例如手机 390×844、平板 1366×1024、桌面 1440×900、工作站 1920×1080、HMI 1024×768、双屏/超宽 2560×1440。
- 每套必须有明确的 `First-glance Signature`：用户第一眼能看到的差异，例如大标题手机卡片、硬边框工控按钮、深色终端、Ribbon 工具栏、三维视口、图表矩阵、浮动小窗。
- 每套必须拉开 `Component Scale`：有的整体控件很小很密，有的按钮和列表很大，有的中等办公密度，有的触控大字号。
- 每套必须拉开背景与容器语言：纯白/浅灰/米色/深蓝/黑灰/玻璃/硬边框/网格底/终端底，不允许连续多套都是白底卡片。
- 每套至少在 `目标分辨率、整体缩放、背景颜色、容器形态、导航骨架、控件密度、字体尺度、边框/阴影` 中变化 5 项以上。
- 如果两套同属浅色风，必须一个偏冷灰硬边框，一个偏暖色大留白，或者一个高密度表格，一个大控件卡片，不能只换主色。
