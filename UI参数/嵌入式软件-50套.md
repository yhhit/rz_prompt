# 嵌入式软件 UI参数（50套）

## 生成目标

生成 50 套嵌入式软件 UI 参数。该类别必须优先理解为以下软件范畴，而不是普通 Web 后台或消费级 App：

- 串口 / 通信配置工具
- 进度流程型
- 列表发现 / 连接控制工具
- 参数表格配置工具
- 双栏操作型
- 日志 / 控制台类工程工具
- 步骤检测型
- 板载轻量终端 / 轻 HMI 式对象界面

核心要求：

1. 必须清晰、稳定、反馈直接。
2. 必须像工程工具或对象控制工具，而不是互联网产品。
3. 不包含具体对象业务逻辑，但要有明确的嵌入式/上位机结构特征。
4. 差异化主要来自：子类型、页面骨架、操作场景、平台气质、信息密度，而不是夸张视觉风格。

---

## 一、总风格规则

- 可采用浅灰、冷灰、银灰、深蓝灰、深炭灰等克制底色。
- 状态色以绿色、橙色、红色、青色为主，用于连接、升级、异常、通信、运行状态。
- 不使用大面积霓虹、糖果色、营销色、社交产品式高饱和渐变。
- 不使用普通 SaaS 后台导航骨架。
- 不使用过度玻璃拟态、互联网卡片首页、复杂业务管理平台结构。
- 不默认做成 PLC/HMI 大按钮操作屏，除非子类型明确是板载轻量终端。

## 二、嵌入式软件真正的差异来源

嵌入式软件不应主要靠以下方式拉差异：

- 奇怪颜色
- 大圆角变化
- 花哨动效
- 装饰性图标
- 互联网产品化卡片层次

真正可用的差异化维度：

1. 子类型
2. 页面骨架
3. 对象连接/调试/升级/配置场景
4. 上位机 or 对象终端
5. 信息密度
6. 日志区 / 参数区 / 状态区 / 对象区组织方式
7. 深浅体系
8. 状态反馈方式

## 技术栈 / 渲染范式优先规则

- Rendering Paradigm: `Engineering desktop utility`
- UI Framework: `Qt Widgets / MFC / WinForms / WPF`
- Component Language: `port selector, tree view, parameter grid, register table, progress panel, log console, status bar`
- Native Control Level: `high`
- CSS Styling Level: `very low`

## OS / Era 使用规则

- 推荐 OS Family: `Windows / Linux / Device Terminal`
- 推荐 OS Era: `Windows 7/10/11 工程工具`、`Linux 工程桌面应用`、`触控本机终端`
- 少量可用: `Windows XP/Windows 7 对象调试工具气质`
- 避免: `iOS/Android 消费App`、`现代云平台后台`、`macOS 精致办公风`
- OS Visual Traits: `传统桌面控件、串口/参数/日志面板、清晰边框、紧凑工具栏、直接状态反馈`
- No Title Bar: `不要操作系统标题栏、不要窗口控制按钮；OS / Era 只体现在工程工具控件、参数面板、日志区和对象终端结构上`

## 四、嵌入式软件结构骨架禁忌

### 常见错误骨架

以下结构会让嵌入式软件跑偏：

- 左侧 SaaS 应用菜单
- 云平台首页 / 运营后台首页
- 顶部互联网图标导航
- 大屏驾驶舱 / 监控台骨架
- PLC/HMI 现场大按钮控制屏骨架（除非是板载终端子类）
- 消费级移动设置页 / 内容流骨架
- 设计软件画布中心骨架

### 适合的正确骨架

- `连接配置`: 上连接区 + 中参数区 + 下日志区
- `固件升级`: 左侧列表 + 右侧步骤流程 + 底部状态条
- `对象发现/连接管理`: 对象列表 + 状态摘要 + 操作区
- `寄存器/参数配置`: 左对象树 + 中参数表 + 右属性栏
- `调试诊断`: 左树 + 中控制 + 右日志/状态
- `日志/控制台`: 控制条 + 大日志面板 + 状态行
- `对象测试/产测`: 测试步骤区 + 结果区 + 状态总结
- `板载轻量终端`: 顶部状态 + 中央触控操作区 + 底部确认区

## 少量套数强差异化规则

当某个大类下只有 6–10 套真实参数时，不能只做同一骨架的配色变化；每套都必须像不同软件。生成时优先遵守以下硬约束：

- 每套必须有不同的 `Target Viewport / UI Scale`：例如手机 390×844、平板 1366×1024、桌面 1440×900、工作站 1920×1080、HMI 1024×768、双屏/超宽 2560×1440。
- 每套必须有明确的 `First-glance Signature`：用户第一眼能看到的差异，例如大标题手机卡片、硬边框工控按钮、深色终端、Ribbon 工具栏、三维视口、图表矩阵、浮动小窗。
- 每套必须拉开 `Component Scale`：有的整体控件很小很密，有的按钮和列表很大，有的中等办公密度，有的触控大字号。
- 每套必须拉开背景与容器语言：纯白/浅灰/米色/深蓝/黑灰/玻璃/硬边框/网格底/终端底，不允许连续多套都是白底卡片。
- 每套至少在 `目标分辨率、整体缩放、背景颜色、容器形态、导航骨架、控件密度、字体尺度、边框/阴影` 中变化 5 项以上。
- 如果两套同属浅色风，必须一个偏冷灰硬边框，一个偏暖色大留白，或者一个高密度表格，一个大控件卡片，不能只换主色。
